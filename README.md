# MS NAVIGATOR — защищённый доступ

Готовое Node.js-приложение для размещения на Render с базой PostgreSQL в Neon.
Исходный `MS NAVIGATOR` закрыт серверной авторизацией: без действующей сессии
сервер не отдаёт страницу приложения.

## Как устроен доступ

1. Администратор входит в `/admin` и создаёт одноразовый код.
2. Новый пользователь открывает вкладку «Первый вход», придумывает логин и
   личный пароль, затем вводит код администратора.
3. Сервер атомарно помечает код использованным и создаёт аккаунт. Даже два
   одновременных запроса не смогут применить один код дважды.
4. В дальнейшем пользователь входит по своему логину и личному паролю.
5. При блокировке аккаунта сервер сразу удаляет все его активные сессии.

Полные пароли и полные одноразовые коды в базе не хранятся. Пароли защищены
`bcrypt`, коды и session-токены сохраняются только как SHA-256-хеши. Сессия
находится в cookie с флагами `HttpOnly`, `Secure` и `SameSite=Strict`.

## Развёртывание

### 1. Создайте базу Neon

1. Создайте проект в Neon.
2. Нажмите **Connect**, включите **Connection pooling** и скопируйте строку
   подключения. В имени хоста pooled-строки обычно есть `-pooler`.
3. Никому не отправляйте эту строку и не добавляйте её в Git.

Схема таблиц применяется автоматически при запуске приложения.

### 2. Загрузите проект в GitHub

Распакуйте архив так, чтобы `render.yaml` и `package.json` находились в корне
репозитория, затем отправьте репозиторий на GitHub.

### 3. Создайте сервис Render

Самый простой вариант — **New → Blueprint** и выбор репозитория. Render прочитает
`render.yaml`. Введите секретные переменные:

- `DATABASE_URL` — pooled connection string из Neon;
- `ADMIN_LOGIN` — логин администратора, например `admin`;
- `ADMIN_PASSWORD` — уникальный пароль администратора длиной от 10 символов.

После успешного запуска откройте адрес Render. При первом запуске будет создан
единственный аккаунт администратора. Если администратор уже существует в базе,
изменение `ADMIN_PASSWORD` в Render не перезаписывает его пароль.

### 4. Первый код для пользователя

1. Войдите под администратором.
2. В блоке «Новый код доступа» выберите срок и нажмите «Создать».
3. Сразу скопируйте код: полностью он показывается только один раз.
4. Пользователь выбирает «Первый вход», задаёт свой логин и пароль и вводит код.

## Локальный запуск

Нужен Node.js 20+ и доступная PostgreSQL-база.

```bash
cp .env.example .env
npm install
npm start
```

Откройте `http://localhost:3000`.

## Проверка

```bash
npm run check
```

## Важные правила

- Не размещайте `views/app.html` как публичный статический файл.
- Не переносите `DATABASE_URL` или пароли в клиентский JavaScript.
- Для боевого сервиса используйте длинный уникальный пароль администратора.
- Передавайте одноразовый код конкретному человеку по доверенному каналу.
- Если код ушёл не тому человеку, отзовите его в админке до активации.
